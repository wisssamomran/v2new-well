# خطة التنفيذ المراجعة: نظام الحوكمة الإدارية والأمنية لمدير النظام (ربط حقيقي بالخادم وقاعدة البيانات)

خطة تنفيذية متكاملة لتطوير مركز القيادة الإداري والأمني لمدير النظام (`AdminDashboardPage`) وربطه حقيقياً بخدمات الخادم (`server.ts`) وقاعدة البيانات المحلية الدائمة (`src/server/db.ts` في `.data/dalani_database.json`) لتنفيذ كافة العمليات الإدارية والأمنية الـ 25 بدقة، مع صيانة وحماية باقي أقسام المنصة ووظائف المستخدمين والخرائط تماماً.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> **الالتزامات والضوابط الصارمة المعتمدة:**
> 1. **الحفاظ على المنصة الحالية**: عدم تغيير أو إعادة بناء واجهات المستخدمين والأدوار الأخرى (`visitor`, `seeker`, `advertiser`, `org_manager`, `org_agent`, `moderator`, `verifier`, `reporter_admin`, `support`, `accountant`).
> 2. **الخريطة**: إزالتها فقط من واجهة مدير النظام (`AdminDashboardPage`)، وبقاؤها نشطة وكاملة في الواجهة الرئيسية وصفحات البحث وتفاصيل العقارات.
> 3. **تنفيذ حقيقي من الواجهة لقاعدة البيانات**: كل عملية من العمليات الـ 25 مرتبطة بمسار API حقيقي في الخادم، تُفحص مدخلاته وصلاحياته برمجياً، وتُحفظ نتائجها فعلياً في `.data/dalani_database.json`.
> 4. **أمان الجلسات وحظر الـ IP في الخادم**: إنهاء الجلسة يبطلها فعلياً من الخادم (`/api/admin/sessions/:id/terminate`) وحظر الـ IP يُطبق في طبقة الخادم مع استثناء عنوان المدير لمنع الحظر العرضي.
> 5. **سجل تدقيق رقابي محمي (Append-Only)**: حفظ تلقائي لكافة الإجراءات الحساسة بدون إتاحة أي واجهة للتعديل أو الحذف، ودون تخزين كلمات مرور أو أسرار.
> 6. **نسخ احتياطي واستعادة مفحوصة**: فحص سلامة وتكامل بنية النسخة الاحتياطية قبل السماح بالاستعادة، مع أخذ نسخة أمان تلقائية قبل أي عملية استعادة.
> 7. **فحص حقيقي للتكاملات**: اختبار اتصال حي (Ping / HTTP Test) لبوابات الرسائل والخدمات من الخادم وإرجاع النتيجة الفعلية.
> 8. **الهوية البصرية ودعم الأجهزة**: الالتزام التام بالهوية الحالية (`#16324F` و `#12A889`) مع تجاوب كامل مع الهواتف والأجهزة اللوحية والحواسيب واتجاه RTL.

### 1. نتائج الفحص المسبق للمشروع (Pre-Implementation Audit)

#### أ. بنية المشروع ومسار البيانات الحالي
- **الخادم (`server.ts`)**: تطبيق Express يعمل على المنفذ 3000 ويدمج وسيطات Vite في وضع التطوير.
- **المصادقة والصلاحيات (`src/server/rbac.ts`)**:
  - فحص الهوية عبر ترويسة `x-user-role` أو رمز `Authorization: Bearer <token>`.
  - التحقق من الأدوار عبر وسيطة `requireRoles()`.
  - تسجيل الرقابة الإدارية عبر دالة `recordAuditLog()`.
- **قاعدة البيانات (`src/server/db.ts`)**:
  - تخزين دائم بصيغة JSON في المسار `.data/dalani_database.json`.
  - المخطط الحالي يتضمن: `listings`, `organizations`, `verifications`, `reports`, `tickets`, `auditLogs`, `users`, و `meta`.
- **الواجهة الأمامية (`src/context/AppContext.tsx` و `AdminDashboardPage.tsx`)**:
  - لوحة الإدارة الحالية تحتوي فقط على 4 تبويبات بسيطة (سجل تدقيق، قاموس اليمن، مؤشرات عامة، وسياسات مكتوبة).

#### ب. جدول الفجوات (Gaps Analysis)
| المكون | الوضع الحالي | المتطلب لتغطية العمليات الـ 25 |
| :--- | :--- | :--- |

### 3. ضوابط الأمان والصلاحيات والنسخ الاحتياطي (Strict Guardrails)

1. **فحص الصلاحيات بالخادم**:
   - كافة المسارات الإدارية تبدأ بـ `/api/admin/*` وتمر وجوباً عبر `requireRoles('system_admin')`.
   - يتم التحقق من أن الموظف لا يمنح نفسه صلاحيات أعلى، ولا يمكن تعديل الصلاحيات لمدير النظام نفسه لمنع إقفال النظام بالخطأ.
2. **إنهاء الجلسات الحقيقي**:
   - جدول `activeSessions` بالخادم يحتفظ بمعرف الجلسة `sessionId`, `userId`, `ipAddress`, `userAgent`, و `issuedAt`.
   - استدعاء `DELETE /api/admin/sessions/:id` يحذف الجلسة فوراً من الخادم ويمنع أي طلبات لاحقة باستخدام هذا المعرف.
3. **حظر الـ IP الذكي**:
   - قائمة `blockedIps` في الخادم تفحص كل طلب وارد. إذا كان الـ IP محظوراً، يُرفض الطلب بكود 403.
   - يتم حماية عناوين الـ Localhost وعنوان المدير الحالي من الحظر لمنع إغلاق لوحة الإدارة عرضياً.
4. **سجل تدقيق رقابي محمي (Tamper-Proof Audit Trail)**:
   - سجل التدقيق هو Append-Only في الخادم؛ لا يوجد مسار `DELETE /api/audit-logs` أو `PUT /api/audit-logs`.
   - يتم تدوين التغييرات مع اسم المنفذ والدور والقيمة السابقة والجديدة.
5. **النسخ الاحتياطي المفحوص**:
   - مسار `/api/admin/backups/create` يجمع كافة الجداول والعلاقات وسجل التدقيق ووثائق النظام مع توليد توقيع تحقق SHA256.
   - قبل أي استعادة (`restore`)، يفحص الخادم التوقيع وبنية الكيانات. وإذا كانت سليمة، ينشئ الخادم تلقائياً نسخة احتياطية للحالة الراهنة كإجراء أمان (Safety Snapshot) قبل تطبيق الاستعادة.
6. **فحص التكاملات الفعلي**:
   - فحص بوابات الرسائل (يمن موبايل / سبأفون) وخوادم التخزين السحابي ينفذ طلب شبكة حقيقي (Ping/Fetch) ويسجل زمن الاستجابة (Latency) الفعلي، وإذا تعذر الاتصال تُعرض رسالة الخطأ الحقيقية.

### 4. واجهة المستخدم وتجربة الاستخدام (`AdminDashboardPage.tsx`)

- **خلو تام من الخرائط**: الواجهة مكرسة بنسبة 100% للأدوات الإدارية، الجداول التفاعلية، والمصفوفات الأمنية.
- **تبويبات اللوحة المنظمة**:
  1. `overview`: لوحة القيادة العامة ومؤشرات الأمان والنشاط الحي.
  2. `staff_users`: إدارة حسابات المستخدمين والموظفين (إنشاء، تعطيل، وتعديل).
  3. `permissions`: مصفوفة الأدوار والصلاحيات وتحديد الرؤية والتنفيذ.
  4. `security`: مركز الأمان، متابعة التهديدات، حظر الـ IP، وإنهاء الجلسات النشطة.
  5. `audit`: سجل التدقيق الرقابي المفصل مع فلاتر نوع العملية والمنفذ.
  6. `settings`: إعدادات المنظومة العامة ومفاتيح الخصائص الحية (Feature Flags).
  7. `data_backup`: فاحص سلامة البيانات، إدارة النسخ الاحتياطي والاستعادة، وسجل أخطاء النظام.
  8. `integrations`: شاشة فحص التكاملات الحية (SMS Gateway, Cloud Storage, Email).
  9. `escalations`: مكتب معالجة المشكلات والقرارات المصعدة للإدارة العليا.
- **عناصر التفاعل والتصميم**:
  - جداول بيانات عالية الكثافة مع مؤشرات بأرقام مجدولة `tabular-nums`.
  - نوافذ تأكيد صريحة قبل أي إجراء حساس (إنهاء جلسة، تعطيل حساب، حظر IP، أو استعادة نسخة احتياطية).
  - دعم كامل للغة العربية واتجاه RTL والتجاوب مع مختلف الشاشات.

### 5. خطة التنفيذ المرحلية (Execution Roadmap)

1. **المرحلة 1: تحديث النماذج في `src/types/index.ts`**:
   - تعريف واجهات: `StaffMember`, `GranularPermission`, `ActiveSession`, `SecurityThreat`, `SystemSettings`, `FeatureFlag`, `BackupPoint`, `SystemErrorLog`, و `IntegrationStatus`.
2. **المرحلة 2: توسيع `src/server/db.ts` وتحديث المخطط**:
   - إضافة الجداول والكيانات الجديدة إلى `DatabaseSchema` مع الحفاظ التام على البيانات الحالية في `.data/dalani_database.json`.
   - كتابة دوال الإدارة، الجلسات، التهديدات، النسخ الاحتياطي، وفحص سلامة البيانات.
3. **المرحلة 3: بناء مسارات الخادم في `server.ts` وتأمينها في `rbac.ts`**:
   - برمجة مسارات `/api/admin/*` للعمليات الـ 25.
   - التحقق من رفض أي طلب غير مصرح به بكود 403.
   - تفعيل تسجيل الرقابة الآلي لكافة العمليات الحساسة.
4. **المرحلة 4: ربط طبقة العميل في `src/context/AppContext.tsx`**:
   - توفير دوال استدعاء حقيقية لكل مسار إداري مع التعامل مع حالات التحميل والخطأ وعرض التنبيهات.
5. **المرحلة 5: إعادة بناء وتطوير `AdminDashboardPage.tsx`**:
   - إنشاء واجهة متكاملة بالهوية الأصلية بدون أي خريطة، مع كافة النوافذ والجداول وأدوات التحكم التفاعلية للـ 25 عملية.
6. **المرحلة 6: فحص التوافق وسلامة المنصة الشاملة**:
   - التأكد من أن الخرائط والبحث في الواجهات الأخرى تعمل بسلاسة وبدون أي مساس.
   - تشغيل `lint_applet` و `compile_applet` وحل أي ملاحظات فوراً.
7. **المرحلة 7: التقرير النهائي الشامل**:
   - تقديم تقرير موثق بنتائج اختبارات العمليات الـ 25، وفحص الصلاحيات، والجلسات، والنسخ الاحتياطي، والتكاملات.
